# 周边去哪儿 · 高德周边地点推荐

## 1. 用途与适用场景

用户站在某个位置，想知道"附近有什么值得去的地方"，并要求地点真实、能走过去。

**适用**：单点出发的地点推荐（咖啡馆、餐厅、公园、便利店、书店、药房等）、带步行时间上限的筛选、带数量上限的推荐、要求按远近排序。

**不适用**：多站行程串联（本技能各推荐互相独立，不做 A→B→C 路线）、驾车/公交/骑行方案（如用户明确要求其他交通方式，先说明本技能按步行口径，再按其要求改用对应工具）、跨城行程规划。

**核心承诺**：回答中的每一个地点名称、地址、距离、时长都来自高德工具返回，不推测、不补全、不用直线距离冒充步行距离。

## 2. 输入要素

| 要素 | 说明 | 缺失时 |
|---|---|---|
| 城市 | 用户明示，或起点坐标所在城市 | 从起点逆地理编码得到，或在回答中说明"按坐标所在城市" |
| 起点 | 优先用评测给定的经纬度；若给的是地名/地铁站，先 `maps_geo` 转坐标 | 只给模糊位置时，用最接近的站点/地标坐标，并在回答中注明起点口径 |
| 地点类别 | 咖啡馆 / 餐厅 / 公园 / 便利店 … | 未指定品类时，选 2 类最常见需求各查 1 次，说明是"按附近常见去处"挑的 |
| 步行上限 T | 分钟 | **默认 15 分钟** |
| 数量 N | 家 | **默认 3，硬上限 3**（用户要更多也只给 3，并说明原因） |
| 排序偏好 | 近一点 / 评分高 / 环境好 … | **默认按步行距离由近到远** |

**需求解析示例**
> "我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。"
> → 城市=杭州；起点=该地铁站坐标；类别=咖啡厅；T=15；N=3；排序=步行距离升序。

## 3. 执行流程（按顺序执行，不要跳步）

### 步骤 1 · 确定起点坐标

- 已有经纬度：直接使用，格式为 `经度,纬度`（小数点后 6 位，如 `120.153576,30.287459`）。**经度在前、纬度在后，不要写反**。
- 只有地名/地铁站：调用 `maps_geo(address=地名, city=城市)`，取返回 `location` 作为起点。若有多个同名结果，取 `level` 为地铁站/兴趣点且城市匹配的那条。
- 只有坐标没有城市：可选调用 `maps_regeocode(location=起点)` 取 `city`，用于后续搜索兜底。

### 步骤 2 · 由步行上限换算搜索半径

```
R = T × 80 米，并限制在 [300, 5000] 米
```

依据：步行速度按 1.2 m/s 估算，T 分钟实际可走约 `T×72` 米；路网绕行系数约 1.3，故 T 分钟内可达的直线半径约 `T×55` 米；再留约 40% 余量避免漏掉边界候选，取 `T×80`。

示例：T=15 → R=1200 米；T=5 → R=400 米；T=30 → R=2400 米。

**宁可半径略大、再由真实步行路线过滤**，不要因为半径偏小漏掉合格地点。

### 步骤 3 · 周边搜索候选地点

调用 `maps_around_search`：

| 参数 | 取值 |
|---|---|
| `location` | 起点 `经度,纬度` |
| `keywords` | 场所名词，不要用整句。如"咖啡"而不是"想喝咖啡"，不要带"附近""推荐"等词 |
| `radius` | 步骤 2 算出的 R，**按字符串传入**（如 `"1200"`） |

规则：

1. **同义扩展最多 3 次搜索**：主关键词 + 至多 2 个同义词/上位词。如 咖啡馆 → `咖啡`、`咖啡厅`；餐厅 → `美食`、`中餐厅`；公园 → `公园`、`绿地`。
2. 多次搜索结果**按 `id` 去重合并**，保留名称、地址、`typecode`。
3. 高德周边搜索默认按距离由近到远返回，可直接以返回顺序作为"就近优先"的初排。
4. 单次结果通常 20 条以内，不需要翻页；无需输出的原始 JSON 不要放进回答。

**兜底 3b**：周边搜索为空或明显过少时——

- 先把 `radius` 放宽到 `2R`（仍不超过 5000）再搜一次；
- 仍为空：改用 `maps_text_search(keywords=类别, city=城市)` 做城市级搜索，取前若干个候选走步骤 4 拿坐标，再用直线距离筛出 R 范围内的（此时候选可能较散，回答中说明"周边搜索无结果，已扩大到城市范围查找"）。

### 步骤 4 · 查详情补坐标（关键步骤，不可省略）

`maps_around_search` 与 `maps_text_search` 返回的 POI **只有 `id`、`name`、`address`、`typecode`、`photos`，没有经纬度**。因此必须调用 `maps_search_detail(id=候选POI的id)` 拿到：

- `location`：`经度,纬度` —— 步行路线查询的目的地坐标来源；
- `address`、`type`、`business_area`：地址与类型的最终依据；
- `biz_ext` 中的 `rating`、`cost`、`open_time` 等：**只有实际返回了才可以引用**，没返回就是"未核实"。

调用预算：**最多查 8 个详情**（就近优先，按步骤 3 的返回顺序取前 8 个）。

拿到坐标后：

1. 计算起点到各候选的**直线距离**（haversine 估算即可），按直线距离升序重排；
2. 取前 **6 个**进入步行路线查询（6 个足够覆盖 3 个合格推荐，且控制调用量）；
3. **类型校验**：`type` / `typecode` 与需求明显不符的剔除。参考：咖啡厅 `0505`、中餐厅 `0501`、快餐厅 `0503`、茶艺馆 `0506`、公园 `110101`、便利店 `0602`。例如搜"咖啡"却返回"咖啡器具商店""咖啡豆批发"，应剔除并在需要时说明。

### 步骤 5 · 逐个查询步行路线

调用 `maps_direction_walking(origin=起点坐标, destination=该地点坐标)`，**destination 必须传坐标，不能传地名**。

从返回结果取 `route.paths[0].distance`（米）与 `route.paths[0].duration`（秒），这是回答中距离与时间的唯一来源。

筛选：

- `duration ≤ T × 60` 秒 → 合格，进入候选池；
- `duration > T × 60` 秒 → **不合格，直接排除**，不得列为符合条件的推荐（如需说明，只可概括"另有若干候选步行超过上限已排除"，不要写名称、不要排名）；
- 单点调用失败：重试 1 次；仍失败则该地点不作为推荐，在说明中注明"有 1 处地点步行路线查询失败，未计入"。

调用预算：**路线查询最多 6 次（含重试不超过 8 次）**。若候选特别多，按直线距离顺序依次查询，凑够 3 个合格即停止。

### 步骤 6 · 排序与取舍

1. 默认按**实际步行距离升序**排序；用户表达"优先近一点"时同样按此排序，并在理由中点明远近关系。
2. 用户有其他偏好（评分高、连锁、便宜等）：只在工具确实返回了对应字段时才作为排序依据；无数据支撑的偏好不做排序，改为在说明中写"该偏好无法通过高德数据核实，已按步行距离排序"。
3. 距离相同则步行时间短者优先，其次地址更具体者优先。
4. 只保留前 N 个（N ≤ 3）。
5. **不足 3 个就少推荐**，不为凑数放宽 T 或混入不相关类别。

### 步骤 7 · 生成回答

见第 4 节模板。回答必须包含：一句结论 + 推荐表格 + 简短说明。

## 4. 回答格式

**标准输出（有合格结果）**

```
从{起点名称}出发，步行 {T} 分钟内找到 {k} 家{类别}，按步行距离由近到远：

| # | 地点 | 地址 | 步行距离 | 预计步行 | 推荐理由 |
|---|------|------|---------|---------|---------|
| 1 | ×××咖啡馆 | ××区××路××号 | 约 320 米 | 约 5 分钟 | 本次候选中步行最近，位于××商圈，高德类型：咖啡厅 |
| 2 | ×××咖啡（××店） | ××区××街××号 | 约 650 米 | 约 9 分钟 | 步行 9 分钟可达，地址在××路沿线，顺路好找 |
| 3 | ×××咖啡馆 | ××区××大道××号 | 约 980 米 | 约 14 分钟 | 距离上限内最后一档，步行 14 分钟，仍在 15 分钟内 |

说明
- 距离与时间为高德步行路线规划结果（起点：{起点坐标或站名}），非直线距离。
- 营业状态、安静程度、排队情况：未核实，建议出发前电话确认。
- {可选}另有 2 处候选步行超过 15 分钟，已排除。
```

**结果不足**

```
从{起点}出发、步行 {T} 分钟内，符合条件的{类别}只找到 {k} 家（要求 {N} 家）：

| # | 地点 | 地址 | 步行距离 | 预计步行 | 推荐理由 |
|---|------|------|---------|---------|---------|
| 1 | ××× | ××× | 约 420 米 | 约 6 分钟 | ... |

说明
- 周边 {R} 米范围内共检索到 {m} 个{类别}，其中 {m-k} 个步行超过 {T} 分钟或类型不符，已排除。
- 如需凑够 {N} 家，可以把步行上限放宽到 20 分钟，或换一个更靠近商圈的起点。
```

**无结果 / 工具异常**

```
在{起点}周边 {R} 米范围内没有检索到符合条件的{类别}。
- 高德周边搜索返回 0 条结果（关键词：咖啡，半径 1200 米）。
- 建议：放宽步行上限到 20 分钟，或改为"咖啡/茶饮/甜品"等相近类别再试。

（若为工具异常）
本次高德地点搜索/步行路线查询失败（{简短错误信息}），暂时无法给出可靠推荐，请稍后重试；我不会在没有查询结果的情况下给出地点和路线。
```

### 表达细则

- 地址一律用 `maps_search_detail` 返回的 `address`；若该字段为空（高德偶尔返回空串或 `[]`），改写为"商圈/道路描述（详细地址未提供）"，不要自行拼凑门牌号。
- 距离：≤1000 米写"约 XXX 米"；>1000 米写"约 X.X 公里"。取整到 10 米。
- 时间：由 `duration` 秒换算，四舍五入到分钟，写作"约 X 分钟"；不足 60 秒写"约 1 分钟"。
- 推荐理由：**一句话、40 字以内、至少含一个数据事实**（步行距离/时长排名、POI 类型、地址或商圈、工具返回的评分）。禁止"环境优雅""氛围不错""人少安静"等无依据形容词。
- 表格列固定为：排名、地点、地址、步行距离、预计步行、推荐理由；缺一项即视为不合格回答。
- 不输出原始 JSON、不输出坐标串、不输出 API Key、不解释内部工具调用过程。
- 全文控制在 300 字以内（表格除外），先给结论再给依据。

## 5. 边界与异常处理

| 情形 | 处理 |
|---|---|
| 周边搜索 0 结果 | 先扩到 2R 重搜 → 再用 `maps_text_search` 城市级兜底 → 仍无则如实说明"范围内未找到"，给放宽建议，**不编造地点** |
| 只有 1–2 家达标 | 如实说明找到几家、排除了几家及原因，可给放宽建议；不降低 T 凑数 |
| 全部候选都超过 T | 说明"最近的一处步行约 X 分钟，超出您的 T 分钟上限"，不列为推荐；可询问是否放宽 |
| 工具报错/超时/无返回 | 重试 1 次；仍失败则说明是查询失败而非"没有地点"，不输出任何未经验证的地点 |
| 用户未给起点 | 追问一次起点（站名/地标/坐标）；仍不明则说明无法定位 |
| 用户问安静程度、排队、是否营业 | 统一答"未核实"；仅当 `biz_ext` 明确返回 `open_time` 时才可引用营业时间 |
| 用户要求超过 3 家 | 只给 3 家，说明"按题目口径每次最多推荐 3 个"，可提出分批次再查 |
| 用户要多个类别 | 每类各查一轮，合并后统一按步行距离排序，总数仍 ≤3，并在表格中标明类别 |
| 起点在两地交界/跨城 | 以起点坐标为准，不因行政区划变化更换起点 |
| 用户要求"顺路串起来" | 说明本技能各地点为独立备选，如需串成路线可另做行程规划 |

## 6. 硬性约束（违反即扣分）

1. **步行距离与时间必须来自 `maps_direction_walking` 的 `distance` / `duration`**，不得用直线距离、`maps_distance` 的直线测量值或估算值替代。
2. **不得编造**：地点名称、地址、营业时间、评分、人均、环境、排队情况，凡工具未返回的一律不写或标"未核实"。
3. **不得把超过 T 的地点列为符合条件的推荐**，也不得在推荐表格中出现超时地点。
4. **推荐数量 ≤ 3**，且每个地点都是同一起点的独立备选，不串成多站行程。
5. **每个推荐必须五项齐全**：名称、地址、步行距离、预计步行时间、一句推荐理由。
6. 地点必须是高德搜索真实返回的 POI，不得用记忆中的店名代替查询结果。
7. 不因"看起来更知名"而调整排序，排序必须能被距离/时间数据解释。

## 7. 回答前自检清单

- [ ] 每个地点都能对应到一次真实的周边搜索/关键词搜索返回？
- [ ] 每个距离和时间都来自该地点的步行路线查询结果？
- [ ] 所有推荐的 `duration` 都 ≤ T？超时的没有出现在表格里？
- [ ] 数量 ≤ 3，且用户要求的类别都满足？
- [ ] 排序与"优先近一点"一致，理由能解释排序？
- [ ] 营业状态/安静/排队等无依据信息已标注"未核实"？
- [ ] 结果不足或工具失败时，是否已如实说明并给出放宽建议？

## 8. 工具速查（高德 MCP Server，官方 12 工具）

| 工具 | 本技能用途 | 关键参数 |
|---|---|---|
| `maps_around_search` | 主查询：起点周边按类别搜 | `location`、`keywords`、`radius` |
| `maps_text_search` | 兜底：城市级关键词搜 | `keywords`、`city` |
| `maps_search_detail` | **取坐标/地址/类型**（搜索接口不返回经纬度） | `id` |
| `maps_direction_walking` | 步行距离与耗时（唯一口径） | `origin`、`destination`（均为 `经度,纬度`） |
| `maps_geo` | 地名/地铁站 → 坐标 | `address`、`city` |
| `maps_regeocode` | 坐标 → 城市/行政区 | `location` |

- 坐标格式统一 `经度,纬度`，六位小数，**不要写反**。
- 若运行环境中的工具名带后缀（如 `maps_direction_walking_by_coordinates`、`maps_detail_search`），按参数含义对应调用，**不要因名称差异跳过步行路线查询**。
- 步行查询返回多个方案时取 `paths[0]`（高德首选方案）；只引用其 `distance` 与 `duration`。
- 工具返回 `isError` 或错误文本（如 `Around Search failed: ...`）时按第 5 节处理。

调用预算总览：周边搜索 ≤3 次、POI 详情 ≤8 次、步行路线 ≤6 次（含重试 ≤8 次），整体不超过 20 次工具调用。

## 9. 常见错误（这些写法会直接扣分）

| 错误写法 | 后果 | 正确做法 |
|---|---|---|
| 把周边搜索的返回列表直接整理成推荐 | 没有真实步行数据，数据真实性判 0 | 每个推荐点必须先过 `maps_direction_walking` |
| 用直线距离 ÷ 步行速度估算时间 | 时长与高德返回不一致 | 只引用 `duration` |
| 用"约 500 米"倒推"约 7 分钟" | 同上 | 距离、时间同源于同一次路线查询 |
| 为了凑够 3 家，把 17 分钟的地点放进表格 | 违反硬性时间条件 | 少于 3 家就少推荐，并说明 |
| 写"评分 4.8、环境安静、人不多" | 编造信息，推荐合理性扣分 | 无数据支撑一律"未核实" |
| 用记忆中的连锁店名代替查询结果 | 地点可能不存在或已搬迁 | 名称必须来自搜索结果 |
| 把 `destination` 写成店名 | 路线查询失败或坐标解析错 | 传 `经度,纬度` |
| 把 `经度,纬度` 写成 `纬度,经度` | 结果跑到另一个城市 | 经度在前，六位小数 |
| 输出一大段 JSON 或坐标串 | 表达清晰度扣分 | 只给表格 + 说明 |
