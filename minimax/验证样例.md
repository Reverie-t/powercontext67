# 验证样例

## 要改什么

实现 `sample_app/tasks.py` 里的 `filter_tasks(tasks, status)`。

- 只留下 `status` 字段和参数完全相同的任务，保持原来的相对顺序。
- 参数是 `None` 或空字符串时，返回全部任务，顺序不变。
- 没有命中时返回空列表，不抛异常。
- 返回新列表，不改传入的列表。

## 哪些原有行为必须保持

`sort_tasks` 按 `priority` 从高到低，相同优先级按 `name` 升序，并且不改传入的列表。对应测试是 `sample_app/tests/test_sort.py`。

## 上下文里必须出现的来源

| 作用 | 路径 | 符号 |
| --- | --- | --- |
| 规格 | `sample_app/spec.md` | `S2` |
| 要改的代码 | `sample_app/tasks.py` | `filter_tasks` |
| 功能测试 | `sample_app/tests/test_filter.py` | `test_filter_exact_status` |
| 回归测试 | `sample_app/tests/test_sort.py` | `test_sort_priority_then_name` |

这些路径写在 `sample_app/manifest.json`。上下文里的正文来自 seekdb 查出来的行，不是命令再去读磁盘现编一份固定答案。

## 初始数据

`snapshots/before/tasks.py` 是改之前的代码。`filter_tasks` 抛出 `NotImplementedError("filter_tasks 尚未实现")`。

## 操作和预期

在 `/data02/quan24/RYB/minimax`：

```bash
PY=/data02/quan24/powercontext/.venv/bin/python
$PY -m minimax check
```

预期：

1. `test_filter` 退出码不是 0，日志里有 `NotImplementedError`。
2. `test_sort` 退出码是 0。
3. `context` 输出里能看到上表四个来源，以及规格里的 `SPEC_TOKEN_ALPHA`。
4. 把规格记号改成 `SPEC_TOKEN_BETA` 并重新 `init` 后，上下文出现 BETA，不再出现 ALPHA。
5. 进程退出后重新执行 `context`，输出里有待办「实现 filter_tasks」和验证记号 `pc-restart-7f3a`。这两句只写在 PowerContext 里。

设置 `MINIMAX_API_KEY` 后再跑 `check`，还会多两步：MiniMax 改写 `tasks.py`，同一组测试全部通过。记录在 `records/minimax_exchange.json` 和 `records/test_after.log`。

## 重置

```bash
$PY -m minimax reset
```

这会删掉 `data/` 里的 seekdb 和 PowerContext 库，并把 `sample_app/tasks.py` 恢复成 `snapshots/before/tasks.py`。规格文件如果被手工改过，用仓库里的 `sample_app/spec.md` 覆盖回去。
